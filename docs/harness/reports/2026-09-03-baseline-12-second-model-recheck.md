## Blocking finding, ahead of the table

**Two harness surfaces assert this repo has no i18n layer. It does.**

- `.agents/skills/deep-review/SKILL.md:67` — *"Do not report a missing `t()` call
  or any i18n gap. CraftHub has no i18n layer: `<html lang="en">` and all
  user-visible strings are hardcoded English, by decision. A finding that asks
  for translation infrastructure is a finding against the reviewer."*
- `.agents/skills/qa-report/SKILL.md` (CraftHub specifics, last bullet) — *"There
  is no jest in this repo, and no i18n: strings are hardcoded English, so never
  plan a translation-coverage sweep or imply `t()` calls."*

`apps/web/package.json:33,39` (`i18next` ^26.4.0, `react-i18next` ^17.0.12),
`package.json:50-52` (`i18n:parity`, `i18n:raw-strings`, `i18n:check`),
`scripts/guardrails/i18n-parity.mjs`, `scripts/guardrails/i18n-raw-strings.mjs`,
and the whole i18n section of the root `AGENTS.md` (`CLAUDE.md` is a symlink to it).
`apps/web/index.html:2` still says `lang="en"`, which is probably what the stale
claim was written against, but the guardrails are live and `.agents/skills/i18n/`
exists as a skill.

This is not a slimming question — it is a correctness defect that instructs a
review agent to suppress true findings against a gate that actually runs. It
should be fixed before any Track C deletion lands, independently of this recheck.
