## Decisions for a Human

### Ports 3333 / 5173 are owned by `weg/retro-doc` (no bug id — not a LinkHub defect)

- **What's broken:** the nightly loop's core premise. The orchestrator
  health-checks that *something* answers on 3333 and 5173 and treats a response
  as "dev servers up". Another Vite/Node project on its default ports satisfies
  that check perfectly, so the loop ran a full BOOTSTRAP against the wrong
  application.
- **Why not auto-fixed:** killing another project's running dev servers is not
  the loop's call, and the ports cannot be rebound while occupied.
- **Options:**
  1. **Stop retro-doc**, then `npm run nightly -- --hours 8 --fresh`. Simplest;
     costs whoever owns that work their running servers.
  2. **Run LinkHub on alternate ports:**
     `bash scripts/nightly/run.sh start --hours 8 --fresh --api-port 3433 --web-port 5273`.
     Non-destructive, but depends on the *uncommitted* `run.sh` edit, and any
     hardcoded `localhost:3333` in e2e/support or `.env` must be checked.
  3. **Commit the `verify_is_linkhub()` preflight first**, then pick 1 or 2. This
     is the only option that stops the same wasted night from recurring silently.
- **Recommendation:** **3, then 1.** Land the preflight (it converts eight silent
  hours into a five-second FATAL), then stop retro-doc and re-run on the default
  ports so nothing else has to be re-pathed. Review the two uncommitted files
  before committing them — this round did not author them and did not review them.

## Learnings

- A liveness probe that only asks "is anything listening?" is not a liveness
  probe. It must assert **identity** — a route only this application serves. The
  in-flight `verify_is_linkhub()` (`GET /profile/__nightly_probe__/posts`, real
  response vs. Fastify's "Route ... not found") is the right shape.
- Vite's default 5173 and the conventional alt-API 3333 are common enough that
  collision with an unrelated repo should be treated as expected, not exotic.
- Routing to `REPORT` instead of grinding `HUNT` against a wrong target was the
  correct call and cost the run ~7.7 hours of unspent deadline rather than ~7.7
  hours of fabricated findings.
- The offline half of the stack (gate + five unit suites) is fully testable with
  no dev server at all. A future BOOTSTRAP should record that baseline *first*,
  as this one did, so a blocked night still produces one durable number.
